The `rilldrop` CLI is a self-contained Go binary. Release installers resolve assets from the standalone [Rilldrop repository](https://github.com/Arnavsharma2/rilldrop).

## Install script

<Tabs>
  <Tab title="macOS and Linux">
    ```bash Terminal
    curl -fsSL https://raw.githubusercontent.com/Arnavsharma2/rilldrop/main/client/public/install.sh | sh
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell Terminal
    irm https://raw.githubusercontent.com/Arnavsharma2/rilldrop/main/client/public/install.ps1 | iex
    ```
  </Tab>
</Tabs>

The scripts download the matching archive and verify it against the release checksum file. They require a published `vX.Y.Z` release.

Pin a release with `RILLDROP_VERSION`:

```bash Terminal
curl -fsSL https://raw.githubusercontent.com/Arnavsharma2/rilldrop/main/client/public/install.sh \
  | RILLDROP_VERSION=v1.0.0 sh
```

```powershell Terminal
$env:RILLDROP_VERSION = "v1.0.0"
irm https://raw.githubusercontent.com/Arnavsharma2/rilldrop/main/client/public/install.ps1 | iex
```

## Build from source

Install Go 1.25 or newer:

```bash Terminal
git clone https://github.com/Arnavsharma2/rilldrop.git
cd rilldrop
go build -o rilldrop ./cli/cmd/rilldrop
```

A source build reports version `dev`; the self-update command is disabled for development builds.

## Verify

```bash Terminal
rilldrop version
```

Expected development output:

```text Output
rilldrop dev
Docs: https://github.com/Arnavsharma2/rilldrop/tree/main/docs
```

For self-hosted deployments, configure the signaling and web origins:

```bash Terminal
export RILLDROP_SERVER=https://files.example.com
export RILLDROP_WEB=https://files.example.com
```

Use separate values only when the API and browser client use different origins.
